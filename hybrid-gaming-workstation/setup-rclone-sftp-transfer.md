# Task: WAN Remote Transfer Layer — Tailscale + rclone SFTP

## Goal

Make **Tailscale + rclone SFTP** the primary file-transfer path between the
MacBook and the Windows PC's `E:\CreativeBridge` share. SMB can remain enabled
for now as a fallback, but it will be removed once rclone SFTP (and optionally
an `rclone mount`) is proven for the remote workflow.

A Tailscale-backed rclone SFTP layer lets the MacBook push large media batches
to the Windows PC across multiple parallel streams, saturating available
bandwidth without exposing a port to the public internet. A GUI rclone client
on the MacBook will manage jobs, schedules, and mounts so the process is not
terminal-only.

The Photoshop watcher and Resolve remote-rendering pipeline stay on top of the
same `E:\CreativeBridge` folder; only the transport path changes.

---

## Logical architecture

```
MacBook (client)                       Windows PC (server)
+--------------------------------+     +----------------------------------+
|  Tailscale app / tailnet IP    |<--->|  Tailscale app / tailnet IP      |
|  RcloneView or rclone CLI      |     |  rclone serve sftp :local:E:/\    |
|  + optional rclone mount       |     |  --addr :2022 --user x --pass y  |
+--------------------------------+     |  Windows Task Scheduler          |
                                       |  (runs at user logon or system   |
                                       |   startup, see note below)         |
                                       +----------------------------------+
                                                        |
                                             E:\CreativeBridge
                                                        |
                                       Photoshop watcher / Resolve queue
```

---

## Dialectical reasoning / trade-offs

### Why rclone SFTP as primary

- **Remote-first workflow:** the MacBook is often not on the same LAN as the
  PC. SMB over a WAN/Tailscale link is per-operation and chatty; every Finder
  click is a network round-trip.
- **Parallel streams:** rclone SFTP can run `--transfers N` concurrent files
  and `--sftp-concurrency M` parallel chunks per file, filling a high-latency
  pipe.
- **Avoids SMB-on-Tailscale bugs:** Windows SMB MultiChannel over Tailscale can
  saturate CPU and collapse throughput (`tailscale/tailscale#17707`).
- **Atomic staging:** files can be uploaded to a staging folder first, then
  moved into the watched folder so the PC never sees partial files.

### Why keep SMB temporarily

- Safety net while rclone SFTP and the chosen GUI are being configured.
- Easy to re-enable if the MacBook is on the LAN and you want quick Finder
  access for a one-off task.
- Resolve and Photoshop on the PC still use the same local path, so SMB removal
  is purely a network-access change.

### Why a GUI

- Terminal scripts are fine for one-shot bulk transfers, but a GUI gives
  visibility into ongoing syncs, job history, folder comparison, and scheduled
  jobs without writing cron.
- Native or near-native options on macOS include RcloneView, the official
  rclone Web GUI, or a dual-pane file manager like ForkLift.


### Known risks

| Risk | Mitigation |
| ---- | ---------- |
| rclone `serve sftp` uses password auth by default | Use a long random password, store it in 1Password, rotate it occasionally. |
| Host keys auto-generated by rclone | Pin them on the MacBook client or use `--sftp-pin-host-key` on first connect. |
| Windows Task Scheduler with plaintext password | Prefer a dedicated local service account or use `--auth-proxy` / SSH key auth if you want to avoid a password file. For home use, a password env var referenced from Task Scheduler is acceptable if the account is low-privilege. |
| MTU / packet-size issues over Tailscale | Tailscale MTU is 1280. If you see stalls, lower MSS or test with `tailscale ping --tsmp`. |
| Direct vs relayed connection | Run `tailscale status` on both sides before benchmarking. Relayed paths are much slower. |
| rclone SFTP server on Windows presents Unix-like shell semantics | The watcher and Resolve paths stay local on Windows, so this mostly affects the client-side path mapping. |
| GUI client permissions on macOS | Grant Full Disk / Files and Folders access as prompted; grant macFUSE/FUSE-T permissions if mounting. |

## Step 1: Verify Tailscale direct connection

On **both** the MacBook and the Windows PC:

```bash
# macOS
sudo tailscale status

# Windows (Admin PowerShell)
tailscale status
```

Look for `direct <ip:port>` between the two nodes. If you see `relay`, fix
that first:

1. Confirm UDP 41641 is not blocked by Windows Firewall on the PC.
2. On the router, ensure UPnP/NAT-PMP is enabled, or forward UDP 41641 to the PC.
3. Try `tailscale ping --until-direct <peer-tailnet-ip>`.

## Step 3: Create a dedicated local account on Windows (recommended)

Instead of running `rclone serve sftp` under your main interactive user, create
a low-privilege local account that only has access to `E:\CreativeBridge`.

```powershell
# Run as Administrator
$Username = "creativebridge"
$Password = ConvertTo-SecureString "<long-random-password>" -AsPlainText -Force
New-LocalUser -Name $Username -Password $Password -Description "SFTP-only drop account for CreativeBridge" -PasswordNeverExpires

# Grant read/write/modify to E:\CreativeBridge only
$Path = "E:\CreativeBridge"
New-Item -ItemType Directory -Path $Path -Force | Out-Null
$Acl = Get-Acl $Path

$Rule = New-Object System.Security.AccessControl.FileSystemAccessRule(
    $Username,
    "Modify,ReadAndExecute,ListDirectory,Read,Write",
    "ContainerInherit,ObjectInherit",
    "None",
    "Allow"
)
$Acl.SetAccessRule($Rule)
Set-Acl $Path $Acl
```

> Note: If Resolve or Photoshop must write to that folder, the watcher/Resolve
> service account also needs matching permissions.

## Step 4: Windows Task Scheduler — autostart rclone SFTP server

Create a scheduled task that runs at user logon (or system startup with the
service account above) and starts `rclone serve sftp`.

### PowerShell script: `C:\ProgramData\rclone\serve-creativebridge.ps1`

```powershell
# serve-creativebridge.ps1
$ErrorActionPreference = "Stop"

$Rclone      = "C:\Program Files\rclone\rclone.exe"
$Listen      = ":2022"
$User        = "creativebridge"
$Pass        = "<long-random-password>"   # or read from a protected env var
$Root        = "E:\CreativeBridge"
$LogDir      = "C:\ProgramData\rclone\logs"

New-Item -ItemType Directory -Path $LogDir -Force | Out-Null
$Timestamp   = Get-Date -Format "yyyyMMdd-HHmmss"
$LogFile     = Join-Path $LogDir "serve-sftp-$Timestamp.log"

& $Rclone serve sftp `:local`:$Root `
    --addr $Listen `
    --user $User `
    --pass $Pass `
    --log-level INFO `
    --log-file $LogFile `
    --stats 1m
```

> `:local`:` is the rclone syntax for "serve a local path through the VFS". On
> Windows you can also write `E:\CreativeBridge` directly after the command.
> `:local:` makes the VFS layer explicit.

### Create the scheduled task

```powershell
# Run as Administrator
$Action = New-ScheduledTaskAction -Execute "powershell.exe" -Argument "-ExecutionPolicy Bypass -WindowStyle Hidden -File C:\ProgramData\rclone\serve-creativebridge.ps1"

# Option A: run when the creativebridge user logs in
$Trigger = New-ScheduledTaskTrigger -AtLogOn -User "creativebridge"

# Option B: run at system startup (requires the task to run as creativebridge)
# $Trigger = New-ScheduledTaskTrigger -AtStartup

$Principal = New-ScheduledTaskPrincipal -UserId "creativebridge" -LogonType Password -RunLevel Highest

$Settings = New-ScheduledTaskSettingsSet -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries -StartWhenAvailable -RestartCount 3 -RestartInterval (New-TimeSpan -Minutes 1)

Register-ScheduledTask -TaskName "rclone-serve-creativebridge-sftp" -Action $Action -Trigger $Trigger -Principal $Principal -Settings $Settings -Force

# Start now to test
Start-ScheduledTask -TaskName "rclone-serve-creativebridge-sftp"
```

Verify it is listening:

```powershell
Get-NetTCPConnection -LocalPort 2022 -State Listen
```

And that it is bound to the Tailscale IP by testing from the MacBook in the
next step.

## Step 5: macOS client — one-shot copy script

Create `~/.config/rclone/rclone.conf` with a remote entry for the PC:

```ini
[pc-sftp]
type = sftp
host = 100.x.x.x          # Windows PC Tailscale IP
port = 2022
user = creativebridge
pass = <obscured-password>
# On first connect run with --sftp-pin-host-key, then remove it.
# host_keys = /Users/milton/.config/rclone/pc-sftp-host_keys.txt
```

To obscure the password:

```bash
rclone obscure "<plaintext-password>"
```

Paste the result into `pass = ...`.

### First connection — pin host key

```bash
rclone --sftp-pin-host-key lsd pc-sftp:
```

This records the host key and prints its SHA256 fingerprint. Save the
fingerprint in your password manager.

### Push a project folder (non-atomic)

```bash
#!/bin/bash
# push-to-pc.sh
PROJECT="$1"   # e.g., /Users/milton/Desktop/photoshop-projects/batch-2026-09-23

rclone copy "$PROJECT" "pc-sftp:/photoshop-projects/batch-2026-09-23" \
  --transfers 8 \
  --sftp-concurrency 64 \
  --sftp-chunk-size 32k \
  --progress \
  --stats 5s \
  --checksum \
  --log-file /tmp/rclone-push-$(date +%Y%m%d-%H%M%S).log
```

Why these numbers?

- `--transfers 8`: 8 files in parallel. Good for many RAW + sidecar sets.
- `--sftp-concurrency 64`: up to 64 in-flight SFTP chunks per file. Fills a
  high-latency pipe for large files.
- `--sftp-chunk-size 32k`: rclone `serve sftp` uses standard 32 KiB packet
  payload, so the client must not ask for a different size. If you later switch
  to OpenSSH as the server, you can raise this to 252k.
- `--checksum`: verifies integrity after copy. Slower but safe for one-shot
  handoffs.

### Push a project folder (atomic staging — recommended)

To prevent the PC watcher from seeing partially uploaded files, upload to a
staging subfolder first, then atomically move the files into the watched
`images/` folder.

```bash
#!/bin/bash
# push-to-pc-atomic.sh
PROJECT="$1"   # e.g., /Users/milton/Desktop/photoshop-projects/batch-2026-09-23
PROJECT_NAME=$(basename "$PROJECT")
SRC="$PROJECT/raw"

# 1. Upload to a staging area with full parallelism
rclone copy "$SRC" "pc-sftp:/photoshop-projects/$PROJECT_NAME/__incoming" \
  --transfers 8 \
  --sftp-concurrency 64 \
  --sftp-chunk-size 32k \
  --progress \
  --stats 5s \
  --checksum \
  --log-file /tmp/rclone-push-stage-$(date +%Y%m%d-%H%M%S).log

# 2. Atomically move staged files into the watched images/ folder
rclone move "pc-sftp:/photoshop-projects/$PROJECT_NAME/__incoming" \
  "pc-sftp:/photoshop-projects/$PROJECT_NAME/images" \
  --transfers 8 \
  --progress \
  --log-file /tmp/rclone-push-move-$(date +%Y%m%d-%H%M%S).log
```

The watcher on the PC only monitors `E:\CreativeBridge\photoshop-projects\*
\images`, so `__incoming` is ignored. After the `move`, complete files appear in
`images/` all at once.

> Note: `rclone move` between two paths on the same SFTP remote is typically a
> server-side rename on the PC, so it is fast and does not re-upload data.

### Pull processed exports back

```bash
#!/bin/bash
# pull-from-pc.sh
PROJECT_NAME="$1"
LOCAL="$HOME/CreativeBridge/$PROJECT_NAME"

rclone copy "pc-sftp:/photoshop-projects/$PROJECT_NAME/processed" \
  "$LOCAL/processed" \
  --transfers 8 \
  --sftp-concurrency 64 \
  --sftp-chunk-size 32k \
  --progress \
  --checksum \
  --log-file /tmp/rclone-pull-$(date +%Y%m%d-%H%M%S).log
```

### Mount as a macOS volume (optional)

If you still want Finder/terminal access, mount the SFTP remote as a folder:

```bash
# Using macFUSE / FUSE-T
mkdir -p ~/CreativeBridge-SFTP
rclone mount pc-sftp: ~/CreativeBridge-SFTP --vfs-cache-mode writes
```

Caveat: mount performance will not match raw `rclone copy` because every
Finder stat is a network round-trip. Use it for browsing, not for bulk ingest.

## Step 6: macOS client — GUI options for managing syncs and mounts

Since you want a GUI to manage what gets synced and when, choose one of these
three paths on the MacBook.

### Option A: RcloneView (recommended)

- Native macOS app built around rclone.
- Two-pane file explorer, drag-and-drop transfers, folder comparison.
- Mount any rclone remote (including SFTP) as a Finder volume.
- Job scheduling with PLUS license.
- Auto-mount on startup.
- Free core features; scheduling is a paid PLUS feature.
- Install: `brew install --cask rclone-ui` or download from
  <https://rcloneview.com/>.

Recommended if you want a single app that covers SFTP transfers, mounts, and
future cloud providers.

### Option B: Official rclone Web GUI

- Bundled with rclone, no extra install.
- Browser-based dashboard: remotes, explorer, mounts, serves, settings.
- No scheduling; manual jobs only.
- Launch: `rclone gui --user admin --pass <password>`.

Useful for quick browsing and ad-hoc transfers, but lacks automation.

### Option C: Dual-pane file manager + rclone CLI

- ForkLift, Commander One, or Path Finder can connect to SFTP/SMB directly.
- Good for browsing and manual transfers, but they do not use rclone's
  parallel SFTP engine.
- Useful as a **Finder replacement** alongside scripted rclone jobs, but not
  as the primary sync engine.

### Recommended mix

- **RcloneView** as the daily GUI for browsing the PC, mounting it when
  needed, and managing scheduled sync jobs.
- **Custom scripts** (`push-to-pc-atomic.sh`, `pull-from-pc.sh`) for the
  heavy Photoshop/Resolve handoffs, because they can be tuned exactly to your
  `--transfers` / `--sftp-concurrency` / atomic-staging needs.

## Step 7: macOS client — mount the SFTP remote via RcloneView

1. Open RcloneView and add a new **SFTP** remote:
   - Host: Windows PC Tailscale IP (`100.x.x.x`).
   - Port: `2022`.
   - User: `creativebridge`.
   - Password: the long random password.
   - Advanced: set `chunk_size` to `32k` to match `rclone serve sftp`.
2. In the **Mount Manager**, create a mount:
   - Remote: `pc-sftp:/`.
   - Mount point: `~/CreativeBridge-SFTP`.
   - VFS cache mode: `writes` for read/write compatibility, or `full` if you
     want aggressive local caching for large previews.
3. Grant RcloneView the macOS permissions it asks for
   (Files and Folders / Full Disk Access, and macFUSE/FUSE-T if needed).

This gives you a Finder-accessible view of the PC for light browsing, while
heavy transfers still go through RcloneView's job manager or your scripts.

## Step 8: macOS client — scheduled jobs (RcloneView PLUS)

If you get the PLUS license, set up scheduled jobs for common handoffs:

| Job | Source | Destination | Direction | Schedule |
| --- | ------ | ----------- | --------- | -------- |
| Drop RAWs to PC | `~/CreativeBridge/*/raw` | `pc-sftp:/photoshop-projects/*/raw` | Copy | Manual or on folder change |
| Pull processed exports | `pc-sftp:/photoshop-projects/*/processed` | `~/CreativeBridge/*/processed` | Copy | After you know a batch is done |
| Nightly sync working folder | `~/CreativeBridge` | `pc-sftp:/` | Copy | 2:00 AM |

Use **Copy**, not **Sync**, for safety so accidental local deletions do not
propagate to the PC.

## Step 9: Update the Windows Photoshop watcher if needed

The watcher currently monitors `E:\CreativeBridge\photoshop-projects`. Since
rclone SFTP is only a transport, the watcher does **not** need to change.

However, because you will use atomic staging (`__incoming` → `images`), add a
safety rule so the watcher explicitly ignores any folder starting with `__`.
This protects against future code changes.

Open `photoshop-watcher/Watcher.ps1` and add this near the top of
`Process-Project`, before scanning `images\`:

```powershell
$projectName = Split-Path $ProjectFolder -Leaf
if ($projectName -match '^__') {
    return
}
```

Also, if you lower `FileSizeStableSeconds` later, test thoroughly first.

## Alternatives considered

| Option | Pros | Cons |
| ------ | ---- | ---- |
| **Keep only SMB + disable MultiChannel** | No new software | Still single-threaded per file; poor remote performance. |
| **Tailscale + `rclone serve webdav`** | Easy macOS Finder mount | WebDAV is not as fast or robust as SFTP for bulk transfer. |
| **Tailscale + `rclone serve nfs`** | Can use native OS mount | Experimental in rclone, historically had severe performance issues. |
| **OpenSSH SFTP on Windows** | Uses standard SSH tooling | More setup (install OpenSSH server, key auth, chroot); harder to autostart cleanly. |
| **rsync over SSH** | Very fast for large sets | Needs WSL or Cygwin on Windows; path mapping becomes complex. |
| **Tailscale + Syncthing** | Continuous sync, versioning | Adds another daemon; versioning can fill disk; conflicts need handling. |

Recommended path: **Tailscale + rclone `serve sftp` as the primary transport,
`rclone mount` (via RcloneView) for occasional Finder browsing, and SMB removed
after validation.**

## Security notes

- Restrict the SFTP account to `E:\CreativeBridge` via NTFS ACLs.
- Do not bind to `:2022` on a public interface. Tailscale IP + firewall is the
  boundary, but binding to all interfaces (`:2022`) is fine because the only
  routable path is the Tailnet.
- Rotate the SFTP password periodically and store it in your password manager.
- Pin the host key on the MacBook client to prevent MITM after the first setup.
